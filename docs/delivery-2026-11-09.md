## 实现与接口

发布 crate 始终 `#![no_std]`，只使用 `core`；普通、开发、构建和目标专用依赖均为空。
没有 `alloc`、`std`、C/FFI、`build.rs`、递归或按运行时输入长度建立的栈数组。
生产源码使用 `#![forbid(unsafe_code)]`。MSRV 为 Rust **1.70.0**。

| 接口 | 能力 |
| --- | --- |
| `encode` / `decode` | 任意长度；调用方提供输出与 `&mut [u32]` 工作区 |
| `encode32` / `encode64` | 专用固定输入长度，输出文本长度可变，最多 44/88 字节 |
| `decode32` / `decode64` | 解码结果必须恰好为 32/64 字节，禁止补零或截断 |
| `encoded_capacity` / `decoded_capacity` | 返回经过溢出检查的容量上界，不冒充精确长度 |
| `encode_scratch_len` / `decode_scratch_len` | 工作区上界，单位为 `u32` 元素 |

每个前导零对应一个前导 `1`；空输入对应空输出。严格拒绝非法字符、非 ASCII、空白和
`0/O/I/l`。容量不足、工作区不足、非法字节、固定结果长度不符及整数溢出有独立错误。
**任何错误均保持整个输出不变**；转换开始后工作区可能改变，失败时也不恢复或擦除。

通用编码每次处理 4 个二进制字节，解码每次处理 5 个 Base58 字符。较大的基数减少了
遍历工作区的次数，最坏时间复杂度仍为二次。32/64 字节内核通过预计算的整数幂系数
完成转换；生成器检查每个乘法、累加、进位、特殊拆分和输出边界。数学方法的 Firedancer
与 five8 归属、许可证及来源 commit 已保留在 [内核说明](fixed-kernel.md)。

## 性能：完整保留未达标结果

最终基准源码 commit 为
[`baf8f42af22f5dd30820f545ba07bf82d87ef561`](https://github.com/LIghtJUNction/z58/commit/baf8f42af22f5dd30820f545ba07bf82d87ef561)。
环境为 Xeon Platinum 8573C、Linux 6.18.57、Rust 1.99.1。两种构建各保留 8100 个样本，
共 **16,200 个最终样本**。每组使用预分配输出、预热、9 次采样、`black_box` 和计时前后
输出验证；输入生成、分配不计时。21 个源码/配置文件的完整快照与 commit 逐项一致。

对照版本固定为 `bs58 0.5.1`、`five8 1.0.0`、`braid58 0.1.0`、`fd_bs58 0.1.0`。
版本、包校验和、源 commit、许可证、CPU/OS/Rust 信息和复现命令均已保存。
测试包括 11 种长度、随机、全零、全 `ff`、长零前缀、重复模式；分别报告通用、专用及消融结果。

下表是启用本机指令集的随机输入中位数，单位 ns/op；比值为最快专用基线耗时除以 z58 耗时。

| 测试 | z58 | five8 | 最快基线 Braid58 | 最快基线 / z58 |
| --- | ---: | ---: | ---: | ---: |
| 32 字节编码 | 55.25 | 67.10 | 31.36 | 0.57× |
| 32 字节解码 | 36.98 | 54.18 | 26.02 | 0.70× |
| 64 字节编码 | 108.24 | 99.93 | 79.73 | 0.74× |
| 64 字节解码 | 99.90 | 127.67 | 32.05 | 0.32× |

便携构建相对最强专用基线的四个比值为 0.84×、1.13×、0.99×、1.18×，同样未达 2 倍。
两种构建的 `gate.json` 都保留 `target_met: false`，没有删除失败结果或改用较弱基线。

通用路径相对 `bs58` 的本机构建随机输入加速如下；这些比值不包含固定长度接口：

| 字节数 | 编码 | 解码 |
| ---: | ---: | ---: |
| 32 | 7.08× | 3.95× |
| 64 | 10.91× | 6.74× |
| 256 | 26.23× | 13.97× |
| 1024 | 19.38× | 18.86× |
| 4096 | 17.87× | 20.01× |

空输入及很短输入存在倒退。共享主机存在明显调度噪声，所有异常样本均保留，中位数未删点。
这些数据描述本次观测；**固定硬件的严格性能验收尚未执行**。工作流已要求专用 runner 与
匹配的 CPU 型号，避免把共享 runner 波动当成验收结论。

专用内核的主要优化空间是标量乘加、进位链和字符转换的并行安排；最强本机基线使用
AVX-512。该判断来自算法依赖结构与消融结果，本次未采集硬件性能计数器。
独立消融已分别测量大 radix、多字节分组、u64/u128、扩大分组、串行/并行字符转换和 radix 58⁴/58⁵。
更大的 u128 分组有利于部分长输入，短输入并不持续受益；完整结果均保留。

完整证据：[性能报告](../comparison/RESULTS.md)、[方法与命令](../comparison/README.md)、
[最终 portable 数据](../comparison/results/verified-2026-11-09-portable/)、
[最终 native 数据](../comparison/results/verified-2026-11-09-native/)。早期原始数据也保留。

## 自动发布状态

已配置 `vX.Y.Z` 推送触发，以及只接受已存在标签的手动发布。发布过程核对版本、标签和
经过完整检查的 commit；仅实际发布步骤注入 `CARGO_REGISTRY_TOKEN`，缺失即停止。
